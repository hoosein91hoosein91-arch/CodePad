## ۱) اتصال به هوش مصنوعی خودت
لانچر ← **AI** ← «سرور خودم». آدرس، مدل، کلید اختیاری، قالب JSON درخواست و مسیر متن در پاسخ قابل‌تنظیم است (قالب آماده: سازگار با OpenAI، Ollama، ساده). «آزمایش اتصال» همان‌جا جواب می‌دهد.
گفت‌وگو، ساخت/اصلاح برنامه، دستور `gemini` در ترمینال، `jibos.gemini` و «بپرس» در نوا همه از همین اتصال می‌گذرند.

**ایجنت با ابزار** برای هر مدلی کار می‌کند، حتی بدون function calling: قرارداد متنی در [AGENT-PROTOCOL.md](AGENT-PROTOCOL.md) (برای آموزش مدل خودت).

نکته‌های شبکه: سرور باید از گوشی در دسترس باشد و هدر `Access-Control-Allow-Origin` بدهد. ساخت اندروید `allowMixedContent` را روشن می‌کند و `http://` از قبل در این نسخه مجاز است. چیزی که به سرور می‌رسد (مثلاً مکان یا خروجی ابزارها) روی همان مسیر می‌رود؛ اگر `http://` روی Wi‑Fi مشترک است، دیگران می‌توانند آن را ببینند. برای مسیر امن از HTTPS یا تونل (Tailscale/cloudflared) استفاده کن.

## ۲) ابزارها و مجوزها
علاوه بر ابزارهای قبلی (Termux، مرورگر، برنامه‌های دستگاه، ویرایش فایل…)، سه مجوز جدا اضافه شده که هر کدام در پنل ایجنت خاموش شروع می‌شود و هر اقدام قبل از اجرا تأیید می‌گیرد:

| مجوز | ابزارها |
|---|---|
| مکان و وضعیت دستگاه | `device_status` (باتری، شبکه، صفحه، زمان) · `get_location` (GPS؛ مجوز مکان اندروید لازم است) |
| شبکه | `network_info` · `scan_network` (nmap روی شبکهٔ خصوصی خودت؛ نیاز به Termux + nmap) |
| نمایش پیام روی صفحه | `show_on_screen` (کارت متنی روی صفحهٔ کدپد؛ HTML اجرا نمی‌شود) |

`scan_network` فقط 192.168.x.x، 10.x.x.x، 172.16‑31.x.x، لینک‌محلی و localhost تا ۱۰۲۴ آدرس را می‌پذیرد؛ هدف عمومی در کد رد می‌شود و فرمان از ورودی ساختاریافته ساخته می‌شود، نه متن آزاد.

## ۳) تم هکری و Cyber Lab
تم مشکی/سبز نئونی با خط‌های اسکن ایستا (بدون انیمیشن مداوم) روی کل برنامه؛ خاموش‌کردن: Cyber Lab ← THEME. دکمهٔ **Cyber** در dock لانچر و **CYBER** در نوار ویرایشگر:
- **TERMINAL**: فرمان در Termux واقعی (stdout/stderr/exit). **NMAP**: اسکن شبکهٔ خودت. **GIT**: clone/status/pull/log/diff.
- **LABS**: ۶ نمونه‌کد ممیزی آموزشی (اسکنر پورت، کشف دستگاه LAN، هدرهای امنیتی وب، TLS، هش رمز، JWT). اسکن شبکه فقط بازهٔ خصوصی؛ بررسی تک‌درخواستی میزبان بیرونی فقط با `--i-own-this`. هیچ نمونه‌ای exploit/حمله/مخفی‌سازی ندارد.
- **NOTES**: خلاصهٔ nmap، git، پورت‌ها، OWASP، سخت‌سازی شبکهٔ خانه. دکمهٔ «تحلیل با AI» خروجی را به مدل خودت می‌دهد.
بار اول یک پیام «استفادهٔ مجاز» نشان می‌دهد.

## ۵) پروژه‌های Python بزرگ (ربات، ابزار شبکه، چندفایلی) — مثال: iran-marketing-radar.zip
در APK، پروژه‌ای که فقط از کتابخانهٔ استاندارد استفاده می‌کند روی **CPython 3.13 بومی** اجرا می‌شود (سوکت واقعی، `urllib`، `sqlite3`، thread، فایل پایدار). چند چیز جلوی اجرای چنین پروژه‌ای را می‌گرفت که حالا درست شده:
- **مسیریابی موتور:** اگر فایل تست پروژه ماژول اصلی (`import bale_bot`) را می‌خواند، کل پروژه به Python WebAssembly می‌رفت (بدون شبکه و sqlite). حالا فقط کدِ قابل‌دسترس از فایل شروع تعیین‌کنندهٔ موتور است. (`python-engine.js` + `python-routing-reachability.test.mjs`)
- **`eval`/`exec`/`__import__` و ماژول‌های فقط‌بومی:** وجود یکی از این سه در کد، پروژه را به WebAssembly می‌فرستاد، حتی اگر همان پروژه `threading`، `socket` یا `sqlite3` می‌خواست که در WebAssembly وجود ندارند. حالا اگر چنین ماژولی import شود، CPython بومی انتخاب می‌شود. (آزمون روی ۱۰۰ برنامهٔ بلند: پاس‌شده ۹۱ ← ۹۵)
- **فایل شروع خودکار:** در ZIP، اسکریپتی که `if __name__ == "__main__":` دارد (نه تست) پیش‌فرض انتخاب می‌شود (`project-zip.js`).
- **آرگومان و متغیر محیطی:** Studio ← ترمینال ← «تنظیم اجرای پروژهٔ فعال». مثال: `BALE_TOKEN=…`، `RADAR_MODEL_MODE=ollama`، آرگومان `--daily-at 09:30`. برای هر پروژه جدا ذخیره می‌شود و فقط روی همین دستگاه می‌ماند (`run-config.js`؛ هر دو موتور CPython و WebAssembly).
- **`getpass`:** کادر ورودی رمز را مخفی می‌کند و جواب را echo نمی‌کند، به‌جای هشدار «Password input may be echoed».
با میزبان واقعی `codepad_runtime.py`، یک بلهٔ جعلی و پایتون ۳٫۱۳ شبیه‌سازی شد: توکن، جفت‌سازی، `/sample`، پیش‌نمایش با دکمه‌ها و ماندگاری `data/bale.sqlite3` درست کار کرد. **روی گوشی و شبکهٔ واقعی بله آزمایش نشده.**
حد: اجرای ۲۴ ساعته به زنده‌ماندن سرویس پیش‌زمینه و تنظیمات باتری اندروید بستگی دارد؛ با Stop یا بستن فرایند متوقف می‌شود.

## ۶) برنامهٔ دسکتاپ ویندوز (مستقل، مثل بازی‌ها)
`CodePad-3.7-Desktop-Windows-x64.zip`: یک برنامهٔ Electron با Chromium همراه خودش. پنجرهٔ مستقل دارد، به مرورگر نصب‌شده یا پورت محلی نیاز ندارد (از پروتکل خصوصی `codepad://app/` استفاده می‌کند و هیچ پورتی باز نمی‌کند). F11 تمام‌صفحه، `--fullscreen` برای شروع تمام‌صفحه، داده‌ها در `%APPDATA%\CodePad`. دوربین و کلیپ‌بورد فقط برای خودِ برنامه مجاز است؛ پنجره‌های خارجی در مرورگر پیش‌فرض باز می‌شوند.
منبع: `resources/windows/desktop/` (main.js و غیره) و `scripts/build-windows-desktop.mjs`. روتر برنامه آدرس غیر http(s) را «خارجی» می‌داند؛ اسکریپت ساخت فقط در کپی دسکتاپ همان یک شرط را برای `codepad:` باز می‌کند (اگر `main.js` تغییر کند ساخت با خطای واضح می‌ایستد). CI روی ویندوز واقعی بسته را می‌سازد و با `scripts/desktop-smoke.cjs` آزمایش می‌کند (پنجره، JSPI، Python + `input()`، ماندگاری) و بعد در انتشار پیش‌نویس می‌گذارد. بدون امضای دیجیتال (SmartScreen هشدار می‌دهد). Python روی WebAssembly است؛ Termux و ابزارهای دستگاه فقط اندروید.

**جایگزین‌های ویندوزی برای بخش‌های اندرویدی** (فقط وقتی `window.cpDesktop` هست؛ نسخهٔ اندروید/وب دست‌نخورده است):
- Termux ← PowerShell (`system.js`، فایل موقت `.ps1` با BOM و `-File` تا نقل‌قول و فارسی خراب نشود). تمام محل‌های فراخوانی Termux (`runTermux`، `TermuxBridge`، ترمینال Cyber Lab، ابزار ایجنت، دستور `termux`/`nmap` لانچر) از طریق `studio-core.js` به پوسته می‌روند؛ دستورهای bash در Cyber Lab معادل PowerShell دارند.
- CPython اندروید ← Python واقعی (`desktop_host.py` + همان `codepad_runtime.py` اندروید، پروتکل JSON-lines): `desktop-worker.js` همان قاعدهٔ مسیریابی `python-engine.js` را به کار می‌برد؛ کتابخانهٔ استاندارد (و ماژول‌های فقط‌بومی مثل socket/sqlite3/threading) → Python واقعی، بقیه → WebAssembly. در بستهٔ ویندوز Python «embeddable» 3.13.1 همراه است (بدون tkinter/pip)؛ مسیر Python دلخواه از Studio ← ترمینال.
- ابزارهای دستگاه: مکان (Location ویندوز)، فهرست برنامه‌ها (رجیستری)، بازکردن برنامه (Start Menu)؛ `install_apk` در ویندوز از فهرست ابزارهای ایجنت حذف می‌شود و متن ابزارها «Termux/Android» را به «PowerShell/Windows» تبدیل می‌کند.
- آزمون: `scripts/desktop-system.test.mjs` (پوسته، Python واقعی، ورودی زنده، Stop) و آزمون دودی CI روی ویندوز واقعی. مکان/فهرست برنامه/بازکردن برنامهٔ ویندوز در CI آزمایش نمی‌شود.

## ۷) موسیقی، نقشهٔ حملات سایبری و تم پرنورتر
- **پخش‌کنندهٔ موسیقی** (`music.js`، دکمهٔ ♪): LOCAL (دسکتاپ: پوشهٔ `Music\Phonk - Video Songs` خودکار، قابل‌تغییر؛ بقیهٔ پلتفرم‌ها: انتخاب فایل/پوشه)، RADIO (radio-browser.info با برچسب‌های phonk، drift phonk و… و دکمهٔ «موزیک بعدی»؛ فقط https)، FOCUS (`focus-playlist.js`: فهرست آهنگ برای تمرکز؛ فایل صوتی همراه برنامه نیست، آهنگ‌های موجود در پوشهٔ کاربر با نام فایل تطبیق و پخش می‌شوند، بقیه جست‌وجوی مرورگر). مینی‌پلیر هنگام کدنویسی می‌ماند.
- **نقشهٔ حملات** (Cyber Lab ← ATTACK MAPS): ۶ نقشهٔ زنده. دسکتاپ: داخل پنجره در یک `WebContentsView` ایزوله (این سایت‌ها iframe را نمی‌پذیرند؛ فقط شناسه‌های از پیش‌تعریف‌شده بارگذاری می‌شوند، نه URL دلخواه). اندروید: مرورگر داخلی برنامه. وب: تب جدید.
- **پوستهٔ دسکتاپ:** IPC اعتبارسنجی‌شده با `preload.js`؛ پروتکل `codepad://app/__media/<id>` فقط فایل‌های اسکن آخرِ پوشهٔ موسیقی را (با Range) می‌دهد و از لینک‌ها خارج نمی‌شود.
- **تم HYPER** (پیش‌فرض): رنگ‌های روشن‌تر، کنتراست بالاتر، خطوط و درخشش نئونی، شبکهٔ پس‌زمینه، باران ماتریکس پشت Cyber Lab؛ سه حالت HYPER / ON / OFF.
- آدرس سایت‌های نقشه و سرویس رادیو از محیط ساخت قابل بررسی زنده نبود (دسترسی بسته)؛ با سرور و صفحهٔ آزمایشی تست شدند.

## محدودیت‌های صادقانه
- ایجنت «کنترل کامل گوشی» نیست: به همان مجوزهای اندرویدی و ابزارهای بالا محدود است. خواندن/کنترل مرورگر دیگر، دادهٔ برنامه‌های دیگر و نمایش روی صفحهٔ سایر برنامه‌ها به کد بومی Java (Accessibility/Overlay) نیاز دارد که اضافه نشد.
- روی گوشی واقعی و APK آزمایش نشده (اینجا Android SDK نیست). رابط وب با مرورگر و Termux شبیه‌سازی‌شده تست شده است.
- مدل تشخیص دست همان MediaPipe `hand_landmarker.task` استاندارد است؛ بهبود دقت به مدل/داده‌ی آموزش‌دیده نیاز دارد (فایل را می‌شود با مدل خودت جایگزین کرد).
- آزمون‌های `test:upgrade` و `test:continuous:node` خودِ ۳٫۷٫۰ روی همان سورس پایه هم شکست می‌خورند (قبل از این تغییرات).

## ۷) هاب (Hub)، پایتون سه‌بعدی، کتابخانه‌های آفلاین و آیکون جدید
- **هاب**: یک دکمهٔ «هاب» در نوار ویرایشگر و در dock لانچر. به‌جای دکمه‌های پراکندهٔ Studio / CYBER، همه‌چیز اینجا مرتب است: خانه، پایتون (۳۰ برنامهٔ آمادهٔ قابل اجرا، دسته‌بندی و جست‌وجو)، سه‌بعدی و کتابخانه‌ها، **اخبار هک**، ابزارها (Cyber Lab، Studio، مرورگر، ZIP، موزیک، تم). دکمه‌های قدیمی Studio/CYBER فقط به‌صورت نامرئی برای آزمون‌ها در DOM مانده‌اند. `hub.js`, `hub.css`, `hub-data.js` (تولید از نمونه‌ها).
- **اخبار هک**: Hacker News (جست‌وجوی security/exploit/malware)، Lobsters/security و فهرست CISA KEV؛ فقط لینک‌های https، ذخیرهٔ آفلاین آخرین دریافت. منبع‌ها اینترنت می‌خواهند و CORS باز دارند؛ اگر یکی از دسترس خارج شود بقیه نشان داده می‌شوند.
- **پایتون سه‌بعدی**: `from codepad3d import Scene` (مکعب/کره/متن، دوربین اول‌شخص با WASD و جوی‌استیک، فیزیک ساده، کلیک/تپ) با نمایشگر three.js داخل برنامه؛ روی موبایل هم چون فقط JS/WebGL است. `python-3d.js`, `public/background/codepad3d.py`.
- **کتابخانه‌های JS آفلاین**: در HTML بنویس `<script src="lib:three">` (یا `p5`, `matter`, `chart`)؛ بدون اینترنت در پیش‌نمایش (حتی sandbox) بارگذاری می‌شود. `libs-loader.js` + `public/libs/*`. **توجه:** خروجی «برنامهٔ مستقل/APK» هنوز تگ `lib:` را به‌طور خودکار درون‌خطی نمی‌کند.
- **نوا (Nava)**: فعلاً از ساخت پروژهٔ جدید حذف شد (پروژهٔ شروع = پایتون، الگوها و نمونه‌های «نوا:» پنهان). موتور نوا برای پروژه‌های قدیمی دست‌نخورده می‌ماند تا چیزی باز نشدنی نشود.
- **آیکون و splash جدید** (مکعب نئونی با ترمینال، تولیدشده با کد SVG): `public/favicon.svg`, آیکون‌های اندروید/ویندوز و splash.

## ۸) بخش امنیت هاب (فقط روی دستگاه خودت)
تب **امنیت** در هاب:
- **سایت تمرین تست نفوذ**: `sec_lab_site.py`، سایت عمداً آسیب‌پذیر با ۱۴ مرحله (SQLi ورود و UNION، XSS بازتابی/ذخیره‌شده، IDOR، پیمایش مسیر، کوکی دستکاری‌پذیر، حدس رمز + هش MD5 ضعیف، Open Redirect، تزریق فرمان، SSRF، آپلود ناامن، صفحهٔ دیباگ، CSRF). فقط روی `127.0.0.1:8088` گوش می‌دهد (پورت در کد ثابت است، هدر Host غیرمحلی رد می‌شود)، به اینترنت وصل نمی‌شود، پرچم‌ها `CP{…}` برای هر نصب تصادفی‌اند و هر مرحله راهنما و راه‌حل (با روش دفاع) دارد. تزریق فرمان با پوستهٔ **شبیه‌سازی‌شده** است و پیمایش مسیر روی **فایل‌سیستم مجازی**؛ هیچ فرمان یا فایل واقعی دستگاه در دسترس نیست (آزمون خودکار این را می‌سنجد).
- **اشتراک روی شبکه**: `sec_lan_share.py`، پوشهٔ پروژه (فایل‌های پیوست یا یک `index.html` به‌عنوان سایت) را روی آدرس شبکهٔ محلی منتشر می‌کند؛ دیگران فقط با مرورگر باز می‌کنند. توکن تصادفی در آدرس (قابل‌خاموش‌کردن)، فقط خواندنی، فقط کلاینت‌های شبکهٔ خصوصی، فایل‌های پنهان و خود برنامه اشتراک نمی‌شوند، پیمایش مسیر و پیوند نمادین به بیرون بسته است، لاگ زندهٔ دستگاه‌های متصل.
- **CTF آفلاین**: ۱۲ چالش (Base64، سزار، هگز، لایه‌ای، XOR، شکستن MD5، جعل JWT با alg=none، تحلیل لاگ SSH، فارنزیک هگزدامپ، ویژنر، دودویی، URL دوبار). فقط هش پرچم نگه‌داری می‌شود؛ هر چالش سه راهنما دارد؛ پیشرفت در حافظهٔ دستگاه.
- **تحلیل فایل**: نوع واقعی از روی بایت‌ها، MD5/SHA-1/SHA-256، آنتروپی، رشته‌ها، هگزدامپ، فهرست ZIP/APK با هشدار Zip Slip/بمب ZIP/اجرایی‌ها، پسوند دوگانه. فایل اجرا یا آپلود نمی‌شود.
- **داشبورد شبکهٔ خانه**: `sec_lan_dashboard.py`، اسکن TCP یک بازهٔ خصوصی ≤ /24 با تأیید مالک؛ آی‌پی عمومی رد می‌شود؛ گزارش و توصیهٔ سخت‌سازی.
- **کارت‌های CVE**: از اخبار هک ذخیره و یادداشت‌گذاری؛ با AI شخصی (اگر وصل باشد) توضیح فارسی.
برنامه‌های پایتون این بخش از `socket/sqlite3/socketserver` استفاده می‌کنند و روی **Python واقعی** (ویندوز/اندروید) اجرا می‌شوند؛ در نسخهٔ مرورگر وب پیغام توضیحی می‌دهند. ویندوز بار اول برای اشتراک شبکه اجازه می‌خواهد. منبع نمونه‌ها: `hub-samples/` و ابزارهای تولید داده: `tools/`.
**محدودیت:** روی گوشی و ویندوز واقعی، و دسترسی دستگاه دوم روی وای‌فای واقعی آزمایش نشده؛ آزمون‌ها با میزبان بومی واقعی CodePad و درخواست‌های واقعی روی همین ماشین انجام شده‌اند. در اندروید، مرورگر داخلی برای آدرس‌های `http://127.0.0.1` ممکن است محدودیت cleartext داشته باشد (آزمایش نشده).

## ۹) بدون پنجرهٔ سؤال، سه‌بعدی مقاوم‌تر، ذخیره/اشتراک گزارش
- **پنجرهٔ سؤال حذف شد.** `input()` و `getpass` و `sys.stdin` فقط از کادر **«جواب‌های آماده (هر خط یک جواب)»** زیر ویرایشگر جواب می‌گیرند، مثل ترمینالی که ورودی‌اش یک فایل است. جواب‌ها در خروجی با پرسش چاپ می‌شوند؛ وقتی تمام شدند برنامه یک `EOFError` عادی با پیام فارسی می‌گیرد (گیر نمی‌کند، پنجره‌ای باز نمی‌شود). نمونه‌های هاب جواب‌های آمادهٔ خودشان را دارند (`# stdin:`) و پایان جواب‌ها را مرتب مدیریت می‌کنند. (`codepad_console.py`، ماژول `python-input` از صفحه برداشته شد؛ ورودی زندهٔ JSPI دیگر لازم نیست.)
- **سه‌بعدی Python:** three.js از r170 (فقط WebGL 2) به **r162** برگشت تا روی دستگاه‌ها/WebViewهای فقط‌WebGL 1 هم کار کند؛ ساخت رندرر با چند تنظیم جایگزین امتحان می‌شود؛ خطای نمایشگر (WebGL نبودن، three.js بارگذاری‌نشدن) فوراً به Python می‌رسد با پیام روشن (به‌جای ۱۵ ثانیه انتظار و «نمایشگر باز نشد»)؛ مهلت ۴۵ ثانیه؛ برنامه‌هایی که `codepad3d` یا `js` را import می‌کنند همیشه روی موتور مرورگر اجرا می‌شوند، حتی اگر موتور «بومی» اجباری باشد؛ و **هاب ← سه‌بعدی ← «بررسی سازگاری»** بدون Python دلیل دقیق (کتابخانه، WebGL1/2، راه‌اندازی نمایشگر) را نشان می‌دهد و گزارشش کپی‌شدنی است.
- **ذخیره / اشتراک گزارش:** `codepad.share_file(path_or_text, name=..., title=...)` در Python (و دکمه‌های «ذخیره/اشتراک» در تحلیل فایل، CTF و کارت‌های CVE) کارتی باز می‌کند. **ویندوز:** ذخیره بی‌پرسش در پوشهٔ عمومی `Documents\CodePad\Reports` (نام تاریخ‌دار، هرگز روی فایل قبلی نمی‌نویسد، پسوند اجرایی مثل .bat/.exe مجاز نیست، دکمهٔ «نمایش در پوشه» فقط برای فایل‌های همین پوشه) و `%CODEPAD_REPORTS_DIR%` برای تغییر؛ **اندروید:** انتخابگر فایل سیستم (هر پوشهٔ عمومی مثل Download) و «اشتراک» برگهٔ اشتراک‌گذاری اندروید برای گزارش‌های متنی (`shareText`)؛ **مرورگر:** دانلود و Web Share. داشبورد شبکه گزارشش را همین‌طور تحویل می‌دهد.
**آزمایش‌شده:** برنامهٔ دسکتاپ بستهٔ واقعی (Electron + Python واقعی، روی لینوکس با xvfb): input از جواب‌های آماده، نبودن پنجره، ذخیرهٔ گزارش در پوشهٔ عمومی، رد کردن «نمایش» فایل بیرون از پوشه، ۷ نمونهٔ سه‌بعدی؛ و رندر ۳بعدی در حالت «فقط WebGL1» (با r170 سیاه می‌ماند؛ با r162 کار می‌کند). **آزمایش‌نشده:** اندروید واقعی (انتخابگر ذخیره، برگهٔ اشتراک)، GPU واقعی ویندوز.

**برنامه‌های خروجی‌گرفته (APK / ZIP ویندوز از پروژهٔ خودت) هنوز تعاملی‌اند:** آن‌ها کادر «جواب‌های آماده» ندارند، پس پلیر خروجی با `interactive: true` می‌گوید و `input()` همان‌جا از کاربر نهایی پرسیده می‌شود (پنجرهٔ `python-input` فقط در بستهٔ خروجی می‌ماند). ویرایشگر CodePad هرگز نمی‌پرسد. آزمون مرورگر `scripts/test-live-input.mjs` رفتار جدید ویرایشگر را می‌سنجد.
